# 修改紀錄：修復口說對話麥克風錯誤

- **修改日期**：2026-08-26
- **修改者**：jasonjss
- **修改目的**：修復點選「開始口說對話」時，`navigator.mediaDevices` 為 `undefined` 所導致的啟動失敗，並補上明確的錯誤提示與連線資源清理。

---

## 一、問題描述

點選「開始口說對話」後出現以下錯誤：

```
errorPolicy.js:12 [Start speaking failed] TypeError: Cannot read properties of undefined (reading 'getUserMedia')
    at setupMicStream (speakingLive.js:328:48)
    at startSpeakingSession (speakingLive.js:365:11)
    at async document.getElementById.onclick (main.js?v=1.4.1:887:9)
```

## 二、根因分析

`navigator.mediaDevices` 只有在**安全上下文（Secure Context）**下才存在：

| 開啟方式 | 是否為安全上下文 | `navigator.mediaDevices` |
| --- | --- | --- |
| `https://`（如 GitHub Pages） | ✅ 是 | 存在 |
| `http://localhost:7031` | ✅ 是（localhost 視為安全） | 存在 |
| `http://192.168.x.x:7031`、`http://主機名稱` | ❌ 否 | **不存在（undefined）** |

當頁面是透過 `http://IP` 或 `http://主機名稱`（例如手機連區網 IP 測試）開啟時，`navigator.mediaDevices` 為 `undefined`，直接讀取 `getUserMedia` 就會拋出上述 TypeError。

## 三、修改內容

### 1. `assets/js/speakingLive.js` — `setupMicStream()` 加入環境檢查

**修改前**：直接呼叫 `navigator.mediaDevices.getUserMedia(...)`，環境不支援時拋出難以理解的 TypeError。

**修改後**：

```js
async function setupMicStream() {
    if (!navigator.mediaDevices?.getUserMedia) {
        throw new Error(t('speakingMicUnavailable'));
    }
    mediaStream = await navigator.mediaDevices.getUserMedia({ ... });
    ...
}
```

### 2. `assets/js/speakingLive.js` — `startSpeakingSession()` 加入資源清理

**問題**：`connectLive()` 成功後，若 `setupMicStream()` 失敗，已建立的 Gemini `liveSession` 連線不會被關閉，會殘留資源。

**修改後**：麥克風失敗時先呼叫 `stopSpeakingSession()` 關閉連線，再重新拋出錯誤，讓 `main.js` 的 catch 正常顯示錯誤並回到設定畫面。

```js
await connectLive(topic, score, level, accent);
try {
    await setupMicStream();
} catch (error) {
    await stopSpeakingSession();
    throw error;
}
emitLog('system', t('speakingSessionStarted'));
```

### 3. `assets/js/i18n/locales/zh-TW.js` — 新增錯誤訊息

新增 key `speakingMicUnavailable`：

```
無法存取麥克風：目前環境不支援麥克風（需使用 HTTPS 或 localhost 開啟）。本機開發請改用 http://localhost:7031 開啟，不要使用 http://IP 或 http://主機名稱 的方式。
```

> `ko`、`ja` 語系檔未新增此 key，依 `i18n.js` 的設計會自動回退（fallback）到 `zh-TW` 顯示。

## 四、驗證

1. `node --check assets/js/speakingLive.js` 語法檢查通過。
2. 確認新 i18n key 已存在於 `zh-TW.js`。
3. 用 `grep` 確認 `speakingLive.js` 內只有此一處呼叫 `getUserMedia`，且已加上環境檢查。

## 五、使用者的解決方式

- **開發環境**：請改用 `http://localhost:7031` 開啟（`make dev` 預設即為此網址），不要用 `http://192.168.x.x:7031` 或 `http://主機名稱`。
- **正式環境**：GitHub Pages 為 `https://`，不受影響；自行部署時請務必使用 HTTPS。
- **其他情況**：若已是 HTTPS 仍失敗，請檢查瀏覽器的麥克風權限設定（需允許網站使用麥克風）。
